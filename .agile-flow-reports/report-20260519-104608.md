## Description

After running `bash scripts/template-sync.sh` (via `/upgrade`) and merging the resulting sync PR, the working tree is left dirty. The script writes to `.agile-flow-meta/version` (a git-tracked file) as a side effect, but the sync commit only includes `.agile-flow-version` (root) and the framework files. The meta version tracker is never staged, so every upgrade leaves the repo with an uncommitted modification on `main`.

## Steps to Reproduce

1. Clean working tree on `main` of a freshly-bootstrapped fork (`.agile-flow-meta/version` is empty).
2. Run `bash scripts/template-sync.sh` (or `/upgrade`).
3. Let the script create the sync branch and open a PR.
4. Merge the PR via GitHub.
5. `git checkout main && git pull --ff-only`.
6. `git status` — `.agile-flow-meta/version` is modified.

## Expected Behaviour

The sync script either (a) stages and commits `.agile-flow-meta/version` to the sync branch alongside the other framework files, or (b) does not touch the tracked file at all (writing only to `.agile-flow-version` at the root).

## Actual Behaviour

`.agile-flow-meta/version` is written to (empty → `1.0.7`) but never `git add`'d. After the PR is merged and `main` is pulled, the file remains a working-tree modification. Every subsequent upgrade re-bumps it without committing, so the repo is permanently dirty post-upgrade until the user manually deals with it.
